# Formula Navigator: сборка на Linux и подключение к Excel

## Выбранная схема

Надстройка написана на **C#** и собирается в **`FormulaNavigator64.xll`** для настольного Excel **64-бит под Windows**. Excel-DNA загружает её в Excel, WPF создаёт окна. VBA-проекта в рабочих книгах нет.

**Сборка выполняется в Linux-контейнере. На Windows переносится готовый `.xll`.** Исходники окон написаны непосредственно на C#, поэтому сборка не использует Windows-компилятор XAML/BAML. Основная надстройка нацелена на .NET Framework 4.8; тесты логики работают на .NET 10.

**Версия 1.0.4:** дерево со ссылками на листьях, ширина окон уменьшена вдвое, размещение у правого края Excel. При сборке запускаются 13 групп C#-тестов и проверка упакованного `.xll`: PE32+, x64, DLL и экспорт `xlAutoOpen`. **Работа окон, размещение на мониторах с разным DPI и фокус требуют проверки в Windows Excel.** Инструменты .NET и пакеты NuGet используются внутри Docker.

## Что установить самостоятельно

### На Linux

Нужен **Docker Engine**. Скрипт сборки поддерживает установленный Buildx и классический сборщик Docker, доступный в Docker 29. Инструкция зависит от дистрибутива: [установка Docker Engine](https://docs.docker.com/engine/install/).

Проверить готовность:

```bash
docker version
```

Buildx можно проверить отдельно командой `docker buildx version`. Если Docker отвечает `unknown command: docker buildx` или команда сборки выдаёт `unknown flag: --progress`, используй скрипт ниже. При отсутствии Buildx он включает классический сборщик только для своей команды: `DOCKER_BUILDKIT=0 docker build`. Этот механизм устарел и может исчезнуть в будущих версиях Docker; [описание Docker](https://docs.docker.com/engine/deprecated/#legacy-builder-fallback).

Устанавливать .NET SDK на Linux-хост для этой схемы не требуется. При запуске сборки Docker скачает официальный образ `mcr.microsoft.com/dotnet/sdk:10.0`, а `dotnet restore` загрузит пакеты проекта из NuGet внутрь контейнера. Первый запуск требует доступа к реестру образов Microsoft и NuGet.

### Ошибка доступа к docker.sock

Сообщение `permission denied while trying to connect to the docker API at unix:///var/run/docker.sock` означает, что текущий процесс не может обратиться к Docker. В этом случае сборка ещё не началась; сопровождающие сообщения `Can't add file ... to tar` и `read/write on closed pipe` появляются после отказа подключения.

Проверь группы пользователя и текущего терминала:

```bash
getent group docker
id -nG
```

Если пользователь уже указан в группе `docker`, а `id -nG` эту группу не показывает, активируй её для новой оболочки:

```bash
newgrp docker
docker info --format '{{.ServerVersion}}'
```

После успешной проверки повтори сборку в этой же оболочке. Из корня проекта — `bash tools/build-in-docker.sh`, из папки `tools` — `bash build-in-docker.sh`. Вместо `newgrp` можно полностью выйти из сеанса и войти снова; открытие ещё одной вкладки старого терминала может сохранить прежние группы.

Если пользователя в группе нет, администратор может добавить его командой `sudo usermod -aG docker "$USER"`, после чего также потребуется новый сеанс. Доступ через группу `docker` фактически даёт права root на машине. Подробнее: [настройка доступа к Docker без sudo](https://docs.docker.com/engine/install/linux-postinstall/).

Перед обычной сборкой скрипт проверяет доступ к Docker. Если ошибка сохраняется после обновления сеанса, нужно проверить владельца сокета (`ls -l /var/run/docker.sock`) и конфигурацию Docker.

### На Windows

Нужны Excel 64-бит и **.NET Framework 4.8 или более новая совместимая версия 4.x**. SDK, Developer Pack и Visual Studio для подключения готового `.xll` не нужны.

Разрядность Excel: **Файл → Учётная запись → О программе Excel**.

Наличие .NET Framework можно проверить в PowerShell:

```powershell
Get-ItemPropertyValue 'HKLM:\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full' -Name Release
```

Для версии 4.8+ значение `Release` не меньше `528040`: [проверка версии по документации Microsoft](https://learn.microsoft.com/en-us/dotnet/framework/install/how-to-determine-which-versions-are-installed). Если нужной среды нет, пользователь устанавливает **Runtime** с [официальной страницы .NET Framework 4.8](https://dotnet.microsoft.com/en-us/download/dotnet-framework/net48). Надстройка и Dockerfile не устанавливают ничего в Windows автоматически.

## Собрать готовый файл на Linux

Открыть терминал в корне проекта, где находится `Dockerfile`, и выполнить:

```bash
bash tools/build-in-docker.sh
```

Скрипт сам выбирает способ сборки. С Buildx он экспортирует файлы напрямую. Без Buildx выполняет обычный `docker build`, создаёт временный контейнер из финального образа, копирует три файла через `docker cp` и удаляет этот временный контейнер по его ID. Контейнер для копирования не запускается. При ошибке сборки скрипт останавливается и не копирует результат старой сборки.

Если Buildx установлен, можно обойтись прямой командой:

```bash
docker buildx build --progress=plain --output type=local,dest=./artifacts .
```

## Автоматические релизы GitHub

Workflow [`.github/workflows/release.yml`](.github/workflows/release.yml) запускается на каждый `push`. Он поднимает Docker Buildx, выполняет сборку тем же Dockerfile и публикует `FormulaNavigator64.xll` как asset GitHub Release. Тег и название релиза имеют вид `build-<полный SHA коммита>`, поэтому бинарь всегда можно сопоставить с точной версией исходников. Создание release и загрузка бинаря отдельно повторяются до трёх раз при временных ошибках GitHub API; повторный запуск также переиспользует уже созданный релиз. Если Docker-сборка, тесты или проверка XLL завершаются ошибкой, release не создаётся.

Внутри образа последовательно выполняются:

1. Восстановление зависимостей проекта.
2. Сборка и запуск 13 групп тестов парсера, границ подсветки, ссылок и фильтрации дерева навигации.
3. Сборка C#-надстройки под .NET Framework 4.8 и упаковка Excel-DNA.
4. Проверка формата результата: PE32+, x64, DLL и экспорт `xlAutoOpen`.

Ошибка любого из этих этапов останавливает сборку. Проверка PE не проверяет открытие окон или работу Excel COM: это выполняется на Windows.

После успешной сборки в `artifacts/` появятся:

```text
artifacts/
  FormulaNavigator64.xll
  Navigation.xlsx
  BUILD_AND_INSTALL.md
```

Финальный слой Dockerfile предназначен для выгрузки этих файлов. Его не нужно запускать через `docker run`: Windows-библиотека `.xll` не является Linux-программой.

При необходимости открыть именно среду сборки:

```bash
docker build --target builder -t formula-navigator-builder .
docker run --rm -it --entrypoint bash formula-navigator-builder
```

Если Buildx отсутствует и для `docker build` включён BuildKit, перед первой командой нужно указать `DOCKER_BUILDKIT=0`. В контейнере исходники находятся в `/src`. Инструменты SDK остаются внутри образа.

### NuGet недоступен из контейнера: NU1301

Если `dotnet restore` сообщает `Unable to load the service index` и `Resource temporarily unavailable (api.nuget.org:443)`, проверь доступ к NuGet из обычного терминала Linux:

```bash
curl --head --connect-timeout 10 --max-time 20 https://api.nuget.org/v3/index.json
```

Если здесь приходит HTTP 200, а внутри сборки соединение не устанавливается, можно повторить сборку через сеть хоста. Из корня проекта:

```bash
bash tools/build-in-docker.sh --network=host
```

Из папки `tools`: `bash build-in-docker.sh --network=host`.

Параметр передаёт `--network=host` в Docker: команды сборки используют сеть Linux-машины, на которой работает Docker Engine. Это позволяет проверить, связана ли ошибка с маршрутизацией или доступом к DNS из стандартной сети контейнера, например при использовании DNS-серверов только с IPv6-адресами. Этот вариант не гарантирует устранения всех причин NU1301. Подробнее: [сеть для команд сборки Docker](https://docs.docker.com/reference/cli/docker/buildx/build/#network).

Без параметра сохраняется стандартная сеть Docker. Если используется Buildx, скрипт также передаёт разрешение `network.host`; выбранный сервер BuildKit должен поддерживать и разрешать этот режим. Если NuGet недоступен и из обычного терминала, сначала нужно восстановить доступ к нему через используемую сеть, VPN или прокси.

## Подключить в Excel на Windows

1. Перенести `FormulaNavigator64.xll` из `artifacts/` в постоянную папку Windows, например `%LOCALAPPDATA%\FormulaNavigator\`.
2. Открыть Excel.
3. Перейти в **Файл → Параметры → Надстройки**.
4. Внизу выбрать **Управление: Надстройки Excel → Перейти**.
5. Нажать **Обзор**, выбрать `FormulaNavigator64.xll` и включить надстройку.

Выбирать нужно список **«Надстройки Excel»**. COM используется программно для доступа к ячейкам, но этот `.xll` подключается через обычный список надстроек.

Если Excel сообщает о блокировке файла, перенесённого из Интернета, сначала проверь, что это твой собранный файл, затем используй **Свойства файла → Разблокировать**, если Windows предлагает этот пункт. Не нужно включать все макросы или разрешать доступ к VBA-проектам.

### Проверить, что надстройка загрузилась

Начиная с версии 1.0.1 на вкладке **«Надстройки»** появляется меню **Formula Navigator**. Открой **«Проверить подключение»**: окно показывает версию, полный путь загруженного `.xll`, состояние инициализации и последней регистрации горячих клавиш. Для этой сборки версия должна быть **1.0.4.0**. Это позволяет отличить новую сборку от оставшейся подключённой старой копии.

В этом же меню доступны **«Формула и зависимости»**, **«Зависимые ячейки»** и **«Восстановить горячие клавиши»**. Для проверки клавиш включи английскую раскладку, выдели ячейку, выйди из режима её редактирования и верни фокус в Excel после закрытия окна проверки. Если команда из меню работает, а сочетание — нет, нажми «Восстановить горячие клавиши» и повтори проверку. Другая надстройка может переопределить эти сочетания после нашей регистрации.

Команду также можно вызвать через **Alt+F8**, вручную введя `FormulaNavigator_Status` или `FormulaNavigator_Dependents` в поле «Имя макроса» и нажав «Выполнить». Excel может не показывать команды XLL в списке этого окна; само по себе отсутствие имени в списке не означает ошибку. Эти имена вызывают команды C#-надстройки. [Пояснение автора Excel-DNA](https://groups.google.com/g/ExcelDna/c/j7u0OeDge1o).

Если меню не появилось и ручной вызов команды недоступен, проверь выбранный файл в **Параметры → Надстройки → Надстройки Excel**, а также список **Отключённые элементы**. При замене сборки закрой все процессы Excel и замени файл в той папке, из которой он был подключён. Ошибка, показанная при загрузке или в окне проверки, нужна для дальнейшей диагностики. Работа меню и клавиш требует проверки в Windows Excel; Linux-сборка этого не подтверждает.

## Как пользоваться

Выделить одну ячейку и выйти из режима редактирования её текста. Сочетания работают в Excel; это не глобальные горячие клавиши Windows.

| Действие | Клавиша / элемент |
| --- | --- |
| Открыть зависимости и дерево формулы | `Ctrl+Q` |
| Найти прямые зависимые ячейки по всем листам текущей книги | `Ctrl+Shift+Q` |
| Перемещаться между узлами | `↑` / `↓` |
| Раскрыть / свернуть ветку | `→` / `←` |
| Переключать элементы окна вперёд / назад | `Tab` / `Shift+Tab` |
| Перейти к выбранной ячейке и закрыть окно | `Enter` в дереве или «Перейти» |
| Разобрать формулу выбранной ссылки | `Ctrl+Enter` в дереве; в окне зависимых также кнопка «Формула» |
| Вернуться к предыдущей формуле | `Alt+←` или «Назад» |
| Закрыть окно и вернуться в исходную ячейку | `Esc` или кнопка возврата |
| Перечитать формулу / повторить поиск | «Обновить» |

Окно формулы открывается размером **390×480**, окно зависимых — **360×480** (единицы интерфейса Windows до масштабирования DPI). Это вдвое уже предыдущей версии. Окна размещаются у правого края Excel, в пределах рабочей области его монитора; вложенный инспектор также ориентируется на окно Excel. Оба окна можно перемещать и растягивать, минимальный размер — 300×440. Данные узла расположены в несколько строк с переносом; длинные дополнительные поля сокращаются, полный текст доступен в подсказке. Кнопки поиска переносятся на следующую строку, ограничения поиска раскрываются отдельным блоком.

При открытии фокус переходит в дерево; в окне зависимых после поиска выбирается первая найденная ячейка. `Tab` обходит элементы окна по кругу и не отправляет фокус на лист. Активное дерево или поле формулы отмечается синей рамкой. Возвращаясь в дерево, можно продолжить с выбранной строки.

С версии 1.0.3 окна модальные: пока открыта надстройка, клавиши и щелчки по листу не редактируют книгу. Программный предпросмотр ссылок продолжает выделять ячейки за окном. Закрой окно через `Enter`, `Esc` или крестик, чтобы снова работать с листом. Поиск выполняется порциями с приоритетом ниже ввода и отрисовки, поэтому между порциями можно пользоваться клавиатурой и отменять поиск.

В окне формулы фокус на узле выделяет именно его участок в исходной строке. Для узла, у которого есть адрес, выделяется ячейка или диапазон в Excel, а управление остаётся в дереве. При быстром перемещении стрелками предпросмотр обновляется для последнего выбранного узла. Перемещения не заменяют исходную формулу окна. Значения подвыражений вычисляются по мере просмотра; «Обновить» перечитывает состояние.

Листья дерева представляют ссылки из текущей формулы: ячейки, целые диапазоны, имена и структурированные ссылки. Числа, строки, логические константы, пропущенные аргументы и вычисления без ссылок не создают отдельных узлов. Функции и операции остаются ветками, если содержат ссылки. Например, у `IF(A1>5,B2+10,"none")` конечными узлами будут `A1` и `B2`, а исходная формула внизу останется целиком. Названия аргументов сохраняют исходные позиции даже после скрытия констант.

Для `OFFSET` и `INDIRECT` добавлен лист с вычисленным адресом; ссылки в их аргументах также остаются в дереве. Фокус на вычисленном адресе подсвечивает весь вызов функции. Если адрес не удалось определить, узел показывает причину. Формула без ссылок показывает исходную ячейку и сообщение об отсутствии ссылок. Формулы найденных ячеек автоматически не раскрываются: для их просмотра используется `Ctrl+Enter`.

`Enter` проверяет наличие выбранного адреса, закрывает окно и выполняет окончательный переход после восстановления ввода Excel. Если у узла нет адреса или адрес уже недоступен, окно остаётся открытым и показывает причину; ошибку окончательного перехода Excel надстройка показывает отдельно. `Esc` закрывает окно и возвращает в исходную ячейку. Для просмотра формулы ссылки внутри инспектора используется `Ctrl+Enter`; двойной щелчок раскрывает или сворачивает ветку, как в обычном дереве.

Если `Ctrl+Enter` открыл инспектор из списка зависимых, `Esc` закроет только инспектор и вернёт управление дереву результатов. `Enter` на ссылке во вложенном инспекторе завершит навигацию: закроются оба окна, Excel перейдёт к выбранной ячейке. Закрытие окон при выгрузке надстройки отменяет отложенные действия и не запускает возврат к ячейке.

В окне зависимых ячеек есть группировка по листам, фильтр и отмена поиска. Ввод фильтра и завершение поиска не должны уводить фокус из другого элемента окна или приложения. После изменения книги следует нажать «Обновить»: результаты являются снимком выполненного поиска. При выделении нескольких ячеек команда начинает анализ с активной ячейки.

`Ctrl+Q` временно заменяет стандартную команду Excel «Быстрый анализ». При отключении надстройки восстанавливается штатная обработка обеих комбинаций. Если эти же сочетания заняты Arixcel или другой надстройкой, одновременно использовать их привязки не получится; автоматическое восстановление чужой пользовательской привязки не поддерживается.

## Проверить после подключения

Рядом с надстройкой экспортируется тестовая книга `Navigation.xlsx` (в исходном проекте — `tests/fixtures/Navigation.xlsx`). Это обычный `.xlsx` с небольшим набором формул; компилировать что-либо на Windows для проверки не нужно.

1. Открыть `Navigation.xlsx`, перейти на `Inputs!B2` и нажать `Ctrl+Q`. Без щелчка мышью проверить `↓` / `↑`: выделение должно перемещаться по дереву, а не по листу.
2. Раскрыть `IF`. Проверить условие `A1>5` с листом `A1`, ветку `OFFSET(A1,1,0)` и лист `A3`. У `OFFSET` должны быть листы исходной ссылки `A1` и вычисленного адреса `Inputs!$A$2`; отдельных узлов `5`, `1` и `0` быть не должно.
3. Выбрать вычисленный адрес под `OFFSET`: должен выделиться весь вызов `OFFSET(A1,1,0)`, Excel должен перейти к `Inputs!A2`. Несколько раз переместиться стрелками на соседние узлы: выбор не должен отскакивать назад. Снова выбрать вычисленный адрес и нажать `Enter`: окно должно закрыться, активная ячейка должна остаться `Inputs!A2`, следующая стрелка должна работать уже на листе.
4. Вернуться в `Inputs!B3`: формула `INDIRECT("A"&2)` также должна указывать на `Inputs!A2`.
5. Открыть `Inputs!C2`: одинаковые фрагменты `A1>5` в двух вызовах `IF` должны выделяться отдельно.
6. Для `Inputs!A2` нажать `Ctrl+Shift+Q`. В результатах должны присутствовать `Inputs!B2`, `Inputs!B3`, `Inputs!B4`, `Summary!A2` и `'O''Brien'!A1`.
7. Не используя мышь, выбрать результат на другом листе и нажать `Enter`: окно зависимых должно закрыться, а Excel остаться на выбранной ячейке. Повторно открыть поиск, нажать `Ctrl+Enter` на результате и проверить разбор формулы; `Esc` должен закрыть инспектор и вернуть фокус дереву результатов. Ещё раз открыть вложенный инспектор и нажать `Enter` на ссылке: должны закрыться оба окна, а следующая стрелка должна перемещать ячейку листа от выбранного адреса.
8. Проверить `Inputs!B5` со ссылкой на лист с апострофом и `Inputs!B6` с именем `BaseCell`.
9. Закрыть окна надстройки, изменить `Inputs!A2` на `25` и снова открыть инспектор и поиск: значения должны отражать изменение.
10. Закрыть инспектор крестиком и проверить, что лист снова принимает клавиатуру. Отключить надстройку и проверить восстановление стандартного `Ctrl+Q`.
11. В обоих окнах пройти полный круг `Tab` и обратный `Shift+Tab`: дерево, поле формулы и доступные кнопки должны получать видимый фокус, стрелки должны работать внутри выбранного элемента. В поиске набрать фильтр и проверить, что ввод не прерывается возвратом в дерево. При пустом результате окно должно оставаться доступным с клавиатуры.
12. Проверить `Enter` на узле без адреса: окно не должно закрываться. Быстро выбрать ячейку и нажать `Enter` или `Esc`, не ожидая предпросмотра: после закрытия не должно быть запоздалого перехода либо возврата фокуса. Во время длинного поиска переключиться в другое приложение: завершение поиска не должно активировать окно надстройки.
13. Во время длинного поиска проверить доступность `Tab`, `Esc` и кнопки отмены между порциями обработки. Закрыть окно и снова нажать `Ctrl+Q`: Excel должен оставаться доступным, новое окно должно сразу принимать стрелки. Если есть ссылка на другую уже открытую книгу, проверить окончательный переход через `Enter` также между книгами.
14. Открыть `Inputs!B7`: листьями должны быть только `A1` и `B2`, без `5`, `10` и строки `"none"`; при выборе операции `B2+10` вся операция должна подсвечиваться внизу. Для `Inputs!B8` единственная ссылка `A3` должна сохранить подпись `value_if_false`. Для `Inputs!B9` должно появиться сообщение об отсутствии ссылок, без отдельных узлов `SUM`, `1`, `2` и `3`.
15. Проверить ширину обоих окон и открытие справа, в том числе когда Excel не развёрнут. При наличии нескольких мониторов повторить на мониторах с разным масштабом Windows. Уменьшить ширину до минимальной, проверить видимость кнопок, перенос длинных имён/адресов и доступность формулы, статуса и ограничений поиска.

`Inputs!C3` содержит намеренную ошибку `#DIV/0!` для проверки отображения ошибок. Исходники воспроизводимого генератора книги находятся в проекте: `tools/create_demo_workbook.py`.

## Границы реализации

- Поиск охватывает прямые ссылки по всем листам текущей книги. Сканирование других открытых книг как источников зависимых ячеек не выполняется.
- Ссылки внутри условных веток учитываются как потенциальные зависимости. Фактические адреса `OFFSET` и `INDIRECT` определяются по текущим данным.
- Поддерживаются обычные A1-ссылки, диапазоны, имена и структурированные ссылки, которые удаётся разрешить в исходном контексте. Неоднозначные или неподдерживаемые случаи обозначаются в интерфейсе.
- Внешние книги автоматически не открываются. Перейти можно только в уже открытую книгу.
- Разбор формулы и вычисление узлов — разные операции. Если безопасно вычислить узел нельзя, дерево и исходный текст остаются доступными, а причина показывается отдельно. Неизвестные пользовательские функции и макрофункции ради просмотра не вызываются.
- Лексические области `LET`/`LAMBDA`, скрытые зависимости пользовательских функций, трёхмерные ссылки и отдельные сценарии динамических массивов не покрываются полностью. Это не полный клон вычислительного движка Excel.
- Исходная формула, значения и форматирование рабочей книги не переписываются. Навигация меняет текущий лист и выделение.
- Проверки парсера и PE-файла в Linux не заменяют проверку окон, клавиатуры и COM на конкретной версии Excel.

## Обновить или удалить

Для обновления снять галочку надстройки, закрыть все процессы Excel, заменить `.xll` новой сборкой и снова подключить его. Не заменять загруженный файл при работающем Excel.

Для отключения снять галочку в **Параметры → Надстройки → Надстройки Excel**. После закрытия Excel файл можно удалить из выбранной пользователем папки.
